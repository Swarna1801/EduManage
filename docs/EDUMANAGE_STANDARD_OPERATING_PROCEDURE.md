# EduManage Standard Operating Procedure

## Purpose

This SOP defines the standard operating workflow for onboarding, daily use, governance, and review of the EduManage platform.

## Scope

This procedure applies to all users of the EduManage system:

- Principals
- Teachers
- Parents
- Super Users

## Objective

To ensure EduManage is used consistently for school administration, academic tracking, parent communication, and platform governance.

## 1. School Onboarding Procedure

1. Create the school record in the system.
2. Assign the subscription plan as `basic` or `premium`.
3. Confirm subscription status and expiry details where applicable.
4. Create or activate the principal account.
5. Verify principal login and dashboard access.

## 2. Principal Setup Procedure

1. Principal logs in through `/login` using the `principal` role.
2. Review dashboard for school readiness.
3. Add teacher records manually or generate teacher invite links if the school is on premium.
4. Add student records and verify class, fee, and parent linkage details.
5. Review notifications, attendance overview, marks overview, and operational modules before school go-live.

## 3. Teacher Onboarding Procedure

1. Teacher is created manually by the principal or through a valid one-time invite link.
2. Teacher logs in through `/login` using the `teacher` role.
3. Teacher verifies assigned students and class access.
4. Teacher confirms availability of attendance, marks, timetable, and notification modules.
5. If acting as class teacher, teacher verifies class-student management permissions.

## 4. Parent Onboarding Procedure

1. Parent is created manually or through a one-time parent invite link generated by a teacher.
2. Parent logs in through `/login` using the `parent` role.
3. Parent verifies linked child records.
4. Parent checks access to attendance, marks, fees, timetable, notifications, and leave workflows.

## 5. Daily Operations Procedure

### Teacher Daily Workflow

1. Mark self attendance or presence if required by school policy.
2. Mark student attendance for assigned classes.
3. Upload marks or exam-related entries according to schedule.
4. Review student leave items and class notifications.
5. Update timetable information where applicable.
6. Use parent communication tools according to plan access and school policy.

### Principal Daily Workflow

1. Review dashboard summary.
2. Monitor attendance and marks overviews.
3. Review fee status and pending collections.
4. Send announcements or notifications when required.
5. Review teacher leave requests and operational exceptions.

### Parent Daily Workflow

1. Check student attendance and marks.
2. Review fee updates and notifications.
3. Monitor timetable and leave status.
4. Use communication features if enabled for the school plan.

## 6. Notifications and Communication Procedure

1. Use notifications for official school updates related to attendance, fees, marks, and announcements.
2. Use chat only for schools and users with premium access.
3. Keep communication role-appropriate and tied to student or school workflow.
4. Review unread notifications daily.

## 7. Exam and Academic Review Procedure

1. Teachers create exam entries and upload marks as scheduled.
2. Teachers notify pending subject teachers when coordination is required.
3. Principals review exam analytics and marks overview.
4. Parents access child exam marks through the parent portal.

## 8. Fee Management Procedure

1. Student fee values are maintained in student records.
2. Principals update fee status and payment progress.
3. Fee reminders are sent through notification workflows.
4. Parents review dues and payment-related records from their portal.

## 9. Plan Control Procedure

1. Super User reviews school plan and subscription status.
2. Plan changes are performed through super admin controls.
3. Premium-only workflows must not be used unless the school has premium access.
4. Student limit compliance must be reviewed when onboarding new students.

## 10. Access Control Procedure

1. All users must log in using the correct role.
2. Access must remain limited to role-authorized modules.
3. Invite links must be treated as one-time onboarding assets.
4. Invalid or expired invite links must not be reused.

## 11. Review and Governance Procedure

1. Principals should review operations daily and analytics weekly.
2. Teachers should keep attendance and marks updated on schedule.
3. Super Users should review subscriptions, plan fit, and school-level support needs regularly.
4. Platform issues or unusual workflow failures should be escalated for backend or admin review.

## 12. Success Criteria

EduManage is being used correctly when:

- Users log in through the correct role-based portal
- Attendance and marks are updated on time
- Fee status is visible and actionable
- Parents receive timely visibility into student activity
- Premium workflows are used only where enabled
- School leadership has clear operational oversight

## Summary

EduManage should be operated as a structured school workflow platform, not just a data entry system. Consistent use across onboarding, daily operations, communication, fee tracking, and academic review is what creates value for the school.
